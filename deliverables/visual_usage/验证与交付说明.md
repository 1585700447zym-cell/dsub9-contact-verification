# VS Code / MuJoCo 可视化入口验证

2026-09-18。新增的是使用入口；原 B1/B2/V2 控制器、动力学执行器及完成标准未修改。

## 已验证

- 本机具备 VS Code、Python/Python Debugger 扩展，以及项目使用的 Python/MuJoCo 环境。
- 6 个 VS Code 运行配置覆盖模型查看、已有记录回放、B1/B2/V2 单工况重跑和自选记录回放。
- 新增入口 9 项测试，加上已有模型启动器 5 项，共 14 项通过。检查显示模型与实际模型分离、B1/B2 观察回调不改变轨迹、暂停/单步状态、运行关闭与恢复、独立输出、无效回放数据、后处理失败不降级已完成结果。
- 256 段模型窗口启动与自动关闭检查通过；三个视角已分别渲染并目视检查。视角示例不是桌面截图。
- 实际窗口入口重跑 B1 联合 A ×0.75：3501 个记录采样与原 B1 全部相同，推进 0.2468386021180981 mm，合力峰值 0.024516379773500952 N，结束原因 TIME_LIMIT。
- 完整记录见 [本次仿真结果](../interactive_sessions/20260918_154516_007953_b1_combined_a_scale_0.75_49a144/本次仿真结果.md)、[逐采样核对](../interactive_sessions/20260918_154516_007953_b1_combined_a_scale_0.75_49a144/数值核对.json)。运行时源码副本保留；后续审查仅修复完成后的报告状态处理，并调整整体相机距离，未修改该次实际积分流程。
- 独立审查曾发现“报告生成失败会把已完整完成的仿真改记为 ERROR”的问题，已修复并用两项先失败、后通过的检查验证。完整数值结果与报告状态现在分开保存。
- 提前关闭的界面测试保留为 INTERRUPTED_BY_USER，部分轨迹不伪装为完整实验。

## 验证边界

完整数值重跑验证针对 B1 的一个固定工况，不声称本轮重跑了所有 B2/V2 接触工况。模型与控制器仍为开发仿真，没有完整 CR5 或实物标定。

已通过桌面操作打开用户 VS Code 的“D-sub9可视化仿真”工作区，但该工作区目前处于受限模式。工作区信任属于用户需要亲自决定的设置；尚未把“用户桌面中点击 F5 到窗口出现”的整条流程列为已验证。程序入口、图形查看器启动及数值重跑已在工具执行环境独立验证。
