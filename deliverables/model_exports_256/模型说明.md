# 当前 256 段开发模型

导出日期：2026-09-17。对应 B1 实验代码基线：`1645282`。

文件：`dsub9_convex256_b1_mpr.xml`。这是 MuJoCo 的 MJCF 场景文件，不是 SolidWorks 的可编辑零件文件，也不是替换原始 STEP/STL 的新 CAD 总装。

## 它和原模型有什么关系

1. 原 CAD 在 `DSub9_Deliverables_V4/`，用于显示的对齐 STL 在 `assets/visual/`，均保留。
2. 原场景 `models/dsub9_pair.xml` 使用解析 SDF 表示 9 个孔的阶梯实体，其源码仍在 `plugins/dsub9_hole_sdf/`，没有被删掉。
3. 当前 B1 从原场景生成副本，只将孔的 SDF 碰撞表示换为凸分块孔。针、D 形壳碰撞结构、质量与接触参数沿用原模型。
4. 每个孔的入口段与主孔段各按圆周划分 256 块，9 孔共 `9 × 2 × 256 = 4608` 个孔壁碰撞 geom。256 指圆周离散数量，不是 256 个孔，也不是 CAD 三角面总数。
5. 圆孔由平面近似，主孔最大径向放大量约 0.043300 μm，入口约 0.050830 μm。入口仍是 0.25 mm 深的阶梯扩孔，没有新增倒角。小几何近似并不自动保证动态接触结果完全相同。

生成器在内存里移除 SDF 插件和 SDF geom，只影响新副本，不会回写原 XML。这条路线解决的是使用替代碰撞表示继续开发的问题，不能说原解析 SDF 搜索已经修复。原 Python 解析距离仍可用于独立几何核对。

## 模型设置和控制程序分开存放

本导出包含 B1 使用的 0.2 ms 物理时间步，并关闭 native CCD，使凸碰撞走本轮采用的 MPR 后端。重新加载后核对了主要几何、惯量、接触数组与全部数值求解选项，结果见 `导出核对记录.json`。

XML 不包含 Python 中的 B1 控制循环、受限驱动、保护状态机、联合偏差 reset 和成功判据。因此“打开模型”只能查看场景；完整复现仍须执行 `tools.validation.run_b1_baseline`。

## 打开模型

在 PowerShell 执行以下命令。窗口会占用当前命令行，关闭查看器后命令行才返回。

```powershell
Set-Location -LiteralPath 'D:\dsub9项目计划\first_stage_sim\.worktrees\dsub9-v1-contact-validation'
& 'D:\KEYANRUJIAN\python.exe' -X utf8 -B -m mujoco.viewer --mjcf 'deliverables/model_exports_256/dsub9_convex256_b1_mpr.xml'
```

本机 MuJoCo 3.9.0 对包含中文的绝对 XML 路径出现过文件打开错误，因此上面先进入项目根目录，再传入相对英文路径。不要把命令中的相对路径换成中文绝对路径。

单独复制 XML 不足以打开模型：它通过相对路径引用同一工作树的 `assets` 与 `models/includes`。整个目录结构应保留。原 SolidWorks 模型请用 `.SLDPRT` 或 `.step` 打开，不要尝试用 SolidWorks 打开此 XML。

重新导出并核对：

```powershell
& 'D:\KEYANRUJIAN\python.exe' -X utf8 -B -m tools.usage.export_b1_model
```

这会更新本导出目录的 XML 与核对 JSON。它不会改变原模型、控制参数或原 B1 回合。
