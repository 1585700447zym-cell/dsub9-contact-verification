# 接触异常最小复现与修复可行性判定

2026-09-22。**本项能力已完成：三个反例均缩小为仅两几何体的独立场景，能够准确重现；独立新版试验给出了值得进入完整回归的方向。停止可靠性和训练准入尚未通过。**

## 确认了什么

每个最小场景只有一根圆柱针、一个 8 顶点孔凸块，XML 约 2.4 KB，不引用原项目资产或 SDF 插件。对全模型、只保留涉事碰撞对的全模型及最小场景分别核查，三个反例的接触深度、法向、位置完全一致；圆柱尺寸和世界变换、凸块编译顶点及世界变换也逐值一致。

| 反例 | 原 3.9.0 全模型 | 原 3.9.0 最小场景 |
|---|---:|---:|
| 新 native 异常：针 06 / main218 | 223.602245 μm | 223.602245 μm |
| 旧 native 异常：针 05 / main013 | 539.846678 μm | 539.846678 μm |
| MPR 疑点：针 07 / main179 | 3.570487 μm | 3.570487 μm |

因此，**重现这些静态异常不需要控制器、其余针或动态历史**，问题已经缩小到这对几何体的接触查询路径。这个结论不等于已经解释所有装配受阻，也不证明所有停止波动只有一个原因。

## 微扰说明了什么

新 native 反例沿轴向前进 1 nm 后，返回深度由 223.602245 μm 变成约 0.001010 μm；退后 1 nm 后无接触。旧 native 反例也出现类似的大幅跳变。公共平移 1 mm 后仍有异常。它们支持“极浅接触附近的数值敏感性”这一定位方向，但尚未跟踪到引擎内部某条具体分支。

把长度表达乘以 1000、同时换算检测容差后，native 异常值消失，但网格重编译带来约 0.208 nm 坐标差，MPR 反例还变成了无接触。**这不是可采用的换单位修复**：检查只涉及静态碰撞，质量惯量、驱动及材料响应等动力学量没有相应换算；浮点网格误差也不能忽略。未制作或采用毫米单位动力学模型。

## 版本更新有可行性，但没有正式升级

本机正式环境是 MuJoCo 3.9.0。查询[官方发布页](https://github.com/google-deepmind/mujoco/releases/tag/3.13.0)后，将 3.13.0 的官方 PyPI 二进制包仅放入项目 `tmp/mujoco_3_13_probe`，在独立进程中导入。原安装未改动。

三个相同 XML 在两版中的编译几何、位姿、输入文件哈希逐值一致。固定原来每个反例自己的接触后端与容差，结果如下：

| 反例 | 3.9.0 | 独立 3.13.0 | 如何解释 |
|---|---:|---:|---|
| 新 native，容差 1e-12 | 223.602245 μm | 0.000010158 μm | 未重现原严重异常值 |
| 旧 native，容差 1e-9 | 539.846678 μm | 未返回接触 | 未重现严重异常；浅接触是否漏检仍需完整回归 |
| 旧 MPR，容差 1e-9 | 3.570487 μm | 3.570487 μm | 疑点未改变 |

记录显式核对了接触容差、禁用标志、编译几何及位姿；未穷举两个版本所有有效选项及默认值。因此这里是“同 XML 的版本结果对照”，不是对全部有效物理设置完全一致的证明。

这只是版本可行性检查。尤其“未返回接触”不能自动等同于正确；此处轴向分离上界小于原 1 nm 容差，后续需要正见证与邻域检查。不把 MPR 结果混称为新版 native 的结果。本轮未用新版运行整个装配过程，也未重新评价成功率。

官方 [3.9.0](https://github.com/google-deepmind/mujoco/blob/3.9.0/src/engine/engine_collision_gjk.c) 和 [3.13.0](https://github.com/google-deepmind/mujoco/blob/3.13.0/src/engine/engine_collision_gjk.c) 实现可用于后续追踪；当前没有证据把差异归因到某一个特定修复提交，也未向上游发送问题或文件。

## 建议的下一项完整能力

优先做 **“独立新版 native 环境的全回归与停止验收”**，暂不自定义碰撞器或改几何表示：

1. 固定 3.13.0 的独立运行目录、native 后端及候选容差，核查 API 与有效物理设置的兼容性，保留旧环境。
2. 加入此次新反例及其邻域，复测既有静态见证与分离检查，明确不得漏检对应针孔；不能只要求异常深度变小。
3. 静态通过后，运行两种物理步长下的完整 B2 Y 及停止检查。有限数、保护、接触载荷、步长一致性和持续停稳都要通过。
4. 才在同一新环境重评 B1/B2 七工况；若通过后决定正式迁移，再更新默认入口。旧 SDF 插件还涉及版本兼容，不能直接沿用旧 DLL 宣称已验证。

这一方向有了实测依据，但本项交付不包含升级后的完整回归。当前仍处于能力 A，学习训练尚未开始。

微扰记录包含 15 个报告状态；另有每个反例一次参考计算，合计实际执行 18 次静态前向计算。

## 使用、复现与可视化

可直接解压使用：[独立复现包 ZIP](独立复现包.zip)。

推荐入口是 [独立复现脚本](reproduce.py) 和 [minimal_v2 模型目录](minimal_v2/)。它们合在一起可复制到其他目录运行，仅需 MuJoCo 与 NumPy。`keyframe 0` 保存异常位姿；仅打开 XML 默认零姿态并不等于复现该异常。

```powershell
Set-Location 'D:\dsub9项目计划\first_stage_sim\.worktrees\dsub9-v1-contact-validation'
# 原环境：三个冻结场景静态前向，不运行动力学
& 'D:\KEYANRUJIAN\python.exe' -X utf8 -B 'deliverables\contact_minimal_reproducer\reproduce.py'
# 独立新版：只影响这一个进程的导入顺序
& 'D:\KEYANRUJIAN\python.exe' -X utf8 -B 'deliverables\contact_minimal_reproducer\reproduce.py' --package-path 'tmp\mujoco_3_13_probe'
# 可选：MuJoCo 静态观察窗口，恢复 keyframe 0，可旋转和缩放
& 'D:\KEYANRUJIAN\python.exe' -X utf8 -B 'deliverables\contact_minimal_reproducer\reproduce.py' --view new_native
```

可选窗口只同步显示，不调用 `mj_step`，不代表实时插入仿真；本轮已实测无界面复现路径，未进行手动窗口交互验收。需要保存新结果时增加 `--output 新路径.json`，拒绝覆盖已存在文件。新版包在本机已有；复制复现包到其他机器不会携带该包，使用者须准备所需版本环境。MJB 是 3.9.0 二进制快照，跨版本优先用 XML。
