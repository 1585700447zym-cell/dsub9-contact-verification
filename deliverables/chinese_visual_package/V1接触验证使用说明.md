# D-sub9 V1 接触验证详细使用说明

> 适用对象：第一次接触本项目、Git、Python、MuJoCo 或科研接触数据的用户。
>
> 最重要的结论：本交付验证的是**规定姿态准静态数值模型**。力和力矩**未经实物标定**，不能当成真实插入力、设备安全阈值、机器人控制效果或强化学习 episode。

## 1. 先用一分钟理解这套交付

V1 接触验证把 D-sub9 公头按 12 种冻结工况逐步向 `+Z` 方向移动。每移动 10 微米，程序记录一次：

- 公头受到的六维力/力矩；
- 合力和合力矩；
- 当前接触点数量；
- 接触求解器给出的最大穿透量；
- 当前插入深度和公头原点位置。

每个工况分别使用 `0.0004 s`、`0.0002 s`、`0.0001 s` 三个求解器时间步，共得到 `12 × 3 = 36` 条轨迹。三组都使用相同的 10 微米深度网格，因此比较的是同一规定姿态上的求解结果。

一条命令会生成：

1. 一份结构化轨迹 JSON；
2. 一份可用 Excel 打开的平面 CSV；
3. 一份时间步收敛 JSON；
4. 五张中文曲线图；
5. 一份自动读取数据生成的技术报告。

## 2. 它解决什么问题，不解决什么问题

### 2.1 已解决的问题

- 原有 schema-3 只有峰值摘要，现在增加了逐深度曲线证据；
- 横向偏移、倾斜、联合误差不再只看一个最大值，可以查看载荷随深度如何出现和变化；
- 三个时间步使用相同深度点，可以检查求解器设置变化是否明显改变曲线；
- 有明确、机器可检查的硬门槛和收敛目标；
- 原始轨迹、判定、图片和报告可以互相追溯；
- 原有 `reports/contact_validation_results.json` 保持 schema-3 和原 SHA-256 不变。

### 2.2 没有解决的问题

本交付没有引入或验证：

- 真实材料、摩擦和插入力标定；
- pin/socket 或壳体等效柔顺 V2；
- 机器人、夹具、末端执行器和 F/T 传感器；
- Fixed、Search 或 Adaptive Admittance 控制器；
- 自由动力学插入；
- Failure Boundary 概率网格；
- Residual SAC、Risk Supervisor、Hard Safety Guard 或其他 RL 系统；
- 实物安全阈值和设备选型依据。

## 4. 第一次运行前的环境检查

以下操作都在项目根目录 `first_stage_sim` 中进行。最简单的判断方法是：当前目录下能看到 `README.md`、`models`、`tools` 和 `reports`。

### 4.1 打开 PowerShell

在项目文件夹空白处按住 Shift 并单击鼠标右键，选择“在终端中打开”或“在此处打开 PowerShell”。

### 4.2 检查 Python 和依赖

复制整行命令并按 Enter：

```powershell
& 'D:\KEYANRUJIAN\python.exe' -c "import mujoco, numpy, matplotlib, PIL; print('Python环境正常'); print('MuJoCo', mujoco.__version__)"
```

看到“Python环境正常”和 MuJoCo 版本表示这一步通过。若提示找不到文件，说明当前电脑的 Python 不在 `D:\KEYANRUJIAN\python.exe`，请看第 15.1 节。

### 4.3 检查正式 SDF 插件

```powershell
Test-Path 'build\dsub9_hole_sdf\Release\dsub9_hole_sdf.dll'
```

输出应为 `True`。GitHub 默认不保存 `build` 目录，所以换电脑后可能需要重新编译 DLL。

### 4.4 检查当前 Git 分支和提交

```powershell
git branch --show-current
git rev-parse HEAD
git status --short
```

第一行是分支名，第二行是用于复现的完整提交号。第三条没有输出表示当前文件没有未提交改动；有输出不一定是错误，但复现记录中应说明。

## 5. 一条命令生成全部 V1 交付

在项目根目录执行：

```powershell
& 'D:\KEYANRUJIAN\python.exe' -m tools.validation.run_v1_contact_validation
```

程序按以下顺序工作：

1. 检查旧 schema-3 源文件和 SDF DLL；
2. 执行 12 个工况 × 3 个时间步；
3. 验证 36 条轨迹、深度网格和有限数；
4. 原子写入轨迹 JSON、CSV 和收敛 JSON；
5. 生成五张中文 PNG；
6. 生成技术报告；
7. 打印轨迹数、样本数、总体验收状态、每个输出路径和 SHA-256。

运行时间取决于电脑性能。运行期间不要关闭终端，也不要同时移动项目目录。完成后终端中应看到：

- `轨迹数量：36`；
- 一个大于 36 的样本数量；
- `总体验收：PASS` 或 `总体验收：FAIL`；
- 五类输出的完整路径和 SHA-256。

`FAIL` 不等于程序坏了。它表示实际结果没有满足冻结的科学验收门槛，程序仍会保留数据并正常生成报告。文件缺失、schema 错误、DLL 无法加载或出现不可序列化的非有限数才属于生成故障。

## 6. 只检查现有交付，不重新计算

如果只想确认下载或复制后的文件是否齐全，执行：

```powershell
& 'D:\KEYANRUJIAN\python.exe' -m tools.validation.run_v1_contact_validation --check-only
```

此命令不会运行 MuJoCo，也不会覆盖任何文件。它检查：

- 两份 JSON 的 schema 和完整矩阵；
- 当前 schema-3 源文件 SHA-256 是否与 trace JSON 记录一致；
- CSV 行数是否等于 JSON 样本总数；
- 五张图是否存在、分辨率是否足够、metadata 是否有未标定声明；
- 技术报告中的源哈希和 `PASS/FAIL` 是否与 JSON 一致。

检查文件清单：

```powershell
& 'D:\KEYANRUJIAN\python.exe' -m tools.reporting.generate_manifest --verify
```

看到 `manifest is current` 表示受审文件清单与当前文件一致。若刚刚重生成了结果，应先由维护者重新生成并审查 manifest，再使用 `--verify`。

## 8. 轨迹 JSON 字段字典

文件：`reports/v1_contact_traces.json`，编码为 UTF-8，`schema_version=1`。

### 8.1 顶层字段

| 字段 | 类型 | 含义 |
|---|---|---|
| `schema_version` | 整数 | 当前固定为 `1`；其他版本不能由本工具猜测读取。 |
| `source_contact_results_sha256` | 字符串 | 旧 schema-3 基线文件的 SHA-256，用于证明来源没有被替换。 |
| `trace_count` | 整数 | 正式矩阵应为 `36`。 |
| `timestep_values_s` | 数组 | `[0.0004, 0.0002, 0.0001]`，单位秒。 |
| `spatial_step_m` | 浮点数 | 固定 `0.00001 m`，即 10 微米。 |
| `collision_mode` | 字符串 | 正式 V1 固定为 `sdf`。 |
| `contact_profile` | 字符串 | 未标定基线接触配置名称。 |
| `solver` | 字符串 | MuJoCo 求解器及迭代配置。 |
| `mujoco_version` | 字符串 | 生成数据时使用的 MuJoCo 版本。 |
| `coordinate_convention` | 对象 | 插入轴、深度公式和 wrench 参考坐标说明。 |
| `units` | 对象 | 时间、深度、力、力矩和角度的单位。 |
| `limits` | 对象 | 未标定声明、规定姿态扫描边界和为何不保存运行耗时。 |
| `terminations` | 数组 | 可达终止枚举。 |
| `cases` | 数组 | 12 个冻结工况的完整位姿参数。 |
| `traces` | 数组 | 36 条逐深度轨迹。 |

### 8.2 `cases` 中的工况字段

| 字段 | 单位 | 含义 |
|---|---:|---|
| `name` | — | 唯一工况名。 |
| `x_offset_m` | m | 公头沿任务 X 轴的规定偏移。正值表示 `+X`。 |
| `y_offset_m` | m | 公头沿任务 Y 轴的规定偏移。正值表示 `+Y`。 |
| `roll_rad` | rad | 绕 X 轴滚转角。 |
| `pitch_rad` | rad | 绕 Y 轴俯仰角。 |
| `start_origin_z_m` | m | 扫描开始时公头任务原点的世界 Z 坐标。 |
| `target_depth_m` | m | 规定扫描目标深度。 |

12 个工况包括 `separated`、`aligned`、正负 X/Y 100 微米偏移、正负滚转/俯仰 1.5°、联合偏差 A 和联合偏差 B。

### 8.3 每条 `trace` 的 metadata

| 字段 | 含义 |
|---|---|
| `case` | 对应的工况名。 |
| `collision_mode` | 正式结果应为 `sdf`。 |
| `contact_profile` | 使用的未标定接触配置。 |
| `timestep_s` | 本条轨迹的求解器时间步。 |
| `spatial_step_m` | 本条轨迹的规定深度增量。 |
| `solver` | 求解器和迭代设置。 |
| `samples` | 按深度顺序排列的逐点数据。 |
| `summary` | 从本条扫描得到的终止、峰值和最大穿透摘要。 |

### 8.4 每个 `sample` 的字段

| 字段 | 单位 | 正负号与使用方法 |
|---|---:|---|
| `step_index` | — | 从 0 开始的采样序号。 |
| `depth_m` | m | 从 `start_origin_z_m` 起算的规定插入深度，沿 `+Z` 增大。 |
| `male_origin_z_m` | m | 公头原点世界 Z；等于起点 Z 加 `depth_m`。 |
| `wrench.fx` | N | 作用在公头上的世界/任务 X 向力；正号沿 `+X`。 |
| `wrench.fy` | N | 作用在公头上的世界/任务 Y 向力；正号沿 `+Y`。 |
| `wrench.fz` | N | 作用在公头上的世界/任务 Z 向力；正号沿 `+Z`。 |
| `wrench.tx` | N·m | 关于公头任务原点的 X 轴力矩；按右手定则取正。 |
| `wrench.ty` | N·m | 关于公头任务原点的 Y 轴力矩；按右手定则取正。 |
| `wrench.tz` | N·m | 关于公头任务原点的 Z 轴力矩；按右手定则取正。 |
| `force_norm_n` | N | `Fx/Fy/Fz` 的欧氏范数，不保留方向。 |
| `torque_norm_nm` | N·m | `Tx/Ty/Tz` 的欧氏范数，不保留方向。 |
| `contact_count` | 个 | 该姿态下 MuJoCo 接触点数量。不是接触针的数量。 |
| `penetration_m` | m | 当前姿态中最大的数值接触穿透量。不是材料损伤深度。 |

### 8.5 `summary` 字段

| 字段 | 含义 |
|---|---|
| `case`、`collision_mode`、`contact_profile` | 对应的工况、模型和配置。 |
| `termination` | `SUCCESS`、`EXCESS_PENETRATION` 或 `NUMERICAL_ERROR`。 |
| `final_depth_m` | 实际最后有效/执行深度。 |
| `peak_force_n` | 扫描过程中的最大合力。 |
| `peak_torque_nm` | 扫描过程中的最大合力矩。 |
| `peak_signed_wrench` | 六个有符号分量各自绝对值最大时保留的有符号值；六个分量不一定来自同一个深度点。 |
| `max_contacts` | 单个深度点的最大接触数。 |
| `total_contact_samples` | 各深度点接触数累加，用于数值诊断，不等于独立物理接触事件数。 |
| `max_penetration_m` | 全轨迹最大数值穿透量。 |
| `timestep_s` | 求解器时间步。 |
| `speed_m_s` | `spatial_step_m / timestep_s` 的派生值。由于本任务逐点调用 `mj_forward`，不能把它解释成机器人真实速度。 |
| `spatial_step_m` | 固定深度网格步长。 |
| `steps` | 执行步数。正常有限轨迹通常与 `samples` 数量一致。 |
| `solver` | 求解器配置。 |

正式 JSON 故意不保存 `runtime_s`。运行耗时会随电脑、后台程序和缓存变化，不属于接触证据；省略它可以避免只因耗时不同就改变正式数据哈希。

## 9. 收敛 JSON 字段字典

文件：`reports/v1_timestep_convergence.json`，`schema_version=1`。

### 9.1 顶层字段

| 字段 | 含义 |
|---|---|
| `schema_version` | 当前固定为 `1`。 |
| `reference_timestep_s` | 精细参考时间步，固定为 `0.0001 s`。 |
| `trace_count` | 纳入判定的轨迹数，应为 `36`。 |
| `overall_status` | 所有工况比较的总体 `PASS` 或 `FAIL`。 |
| `limits` | 10%、20%、10 微米和 `1e-12` 等冻结门槛。 |
| `cases` | 每个工况的参考摘要、两组比较和工况状态。 |

### 9.2 每个 `case` 的字段

| 字段 | 含义 |
|---|---|
| `case` | 工况名。 |
| `primary_component` | 主要方向分量：X 偏移用 `fx`，Y 偏移用 `fy`，滚转用 `tx`，俯仰用 `ty`，联合偏差用 `tx`；理想/分离为 `null`。 |
| `reference_termination` | `0.0001 s` 参考轨迹的终止。 |
| `reference_final_depth_m` | 参考终止深度。 |
| `reference_peak_force_n` | 参考峰值合力。 |
| `reference_peak_torque_nm` | 参考峰值合力矩。 |
| `reference_max_penetration_m` | 参考最大穿透量。 |
| `comparisons` | `0.0002` 和 `0.0004` 两组相对参考的比较。 |
| `status` | 该工况两组比较综合状态。 |

### 9.3 每组 `comparison` 的关键字段

| 字段 | 含义 |
|---|---|
| `candidate_timestep_s`、`reference_timestep_s` | 候选和参考时间步。 |
| `relative_limit` | 本候选时间步适用的 10% 或 20% 门槛。 |
| `common_sample_count` | 两条轨迹公共深度区间内参与 RMSE 的点数。 |
| `peak_force_relative_error` | 峰值合力相对差。参考为零时是 `null`。 |
| `peak_torque_relative_error` | 峰值合力矩相对差。参考为零时是 `null`。 |
| `primary_component_normalized_rmse` | 主要有符号分量在公共深度点上的 RMSE，再除以参考曲线最大绝对值。参考全零时是 `null`。 |
| `max_penetration_delta_m` | 与参考最大穿透量的绝对差。 |
| `termination_depth_delta_m` | 与参考终止深度的绝对差。 |
| `finite_pass` | 两条轨迹是否全部有限。 |
| `no_numerical_error` | 是否都没有 `NUMERICAL_ERROR`。 |
| `termination_match` | 终止枚举是否一致。 |
| `primary_sign_pass` | 主要分量是否非零且方向一致；没有方向判据的工况为真。 |
| `termination_depth_pass` | 终止深度差是否不超过 10 微米。 |
| `zero_contact_absolute_pass` | `separated` 和 `aligned` 是否满足 `1e-12` 绝对零载荷门槛。 |
| `peak_force_relative_pass` | 峰值合力是否满足本时间步门槛。 |
| `peak_torque_relative_pass` | 峰值合力矩是否满足本时间步门槛。 |
| `primary_component_rmse_pass` | 主要分量归一化 RMSE 是否满足门槛。 |
| `failed_checks` | 所有未通过检查的机器字段名；空数组表示没有失败项。 |
| `status` | 本组比较的 `PASS` 或 `FAIL`。 |

参考峰值为零时，相对误差写成 `null`，而不是在分母中加入人为 epsilon。这样可以避免把数学上无意义的比值伪装成精确百分比。

## 10. CSV 每一列怎么用

文件：`reports/v1_contact_traces.csv`。编码为 UTF-8 with BOM，Windows Excel 通常可直接正确显示。

| 列名 | 单位 | 含义 |
|---|---:|---|
| `case` | — | 工况名，可作为第一筛选条件。 |
| `collision_mode` | — | 正式 V1 为 `sdf`。 |
| `contact_profile` | — | 未标定接触配置。 |
| `timestep_s` | s | 选择 `0.0004`、`0.0002` 或 `0.0001`。 |
| `spatial_step_m` | m | 固定 `0.00001`。 |
| `solver` | — | 求解器设置。 |
| `termination` | — | 整条轨迹的最终终止原因，每一行重复保存方便筛选。 |
| `step_index` | — | 从 0 开始的深度点序号。 |
| `depth_m` | m | 插入深度，沿 `+Z` 增大。 |
| `male_origin_z_m` | m | 公头任务原点世界 Z。 |
| `fx_n`、`fy_n`、`fz_n` | N | 作用在公头上的有符号力分量，正方向分别为 `+X/+Y/+Z`。 |
| `tx_nm`、`ty_nm`、`tz_nm` | N·m | 关于公头任务原点的有符号力矩，按右手定则。 |
| `force_norm_n` | N | 三个力分量的合力大小。 |
| `torque_norm_nm` | N·m | 三个力矩分量的合力矩大小。 |
| `contact_count` | 个 | 当前深度的 MuJoCo 接触点数。 |
| `penetration_m` | m | 当前深度最大数值穿透量。 |

Excel 中查看某条曲线的简单方法：

1. 选择第一行并开启“筛选”；
2. 在 `case` 中选择工况，例如 `combined_a`；
3. 在 `timestep_s` 中选择 `0.0002`；
4. 用 `depth_m` 作横轴；
5. 根据目的选择 `fx_n`、`tx_nm`、`force_norm_n` 或 `penetration_m` 作纵轴；
6. 不要把三个时间步的行混在一条曲线中。

## 12. 硬门槛、收敛目标和 PASS/FAIL

### 12.1 六个硬门槛

1. 所有正式轨迹数值必须有限；
2. 不得出现 `NUMERICAL_ERROR`；
3. 同一工况三个时间步的终止枚举必须一致；
4. 横向、倾斜和联合工况的主要有符号分量方向必须一致；
5. 相对 `0.0001 s` 的终止深度差不得超过 10 微米；
6. `separated` 和 `aligned` 的零接触载荷不得超过 `1e-12` 绝对门槛。

### 12.2 三个收敛指标

对参考值非零的接触工况，检查：

- 峰值合力相对差；
- 峰值合力矩相对差；
- 主要分量在公共深度区间的归一化 RMSE。

`0.0002 s` 对 `0.0001 s` 的三个指标均应不超过 10%；`0.0004 s` 对参考的三个指标均应不超过 20%。

### 12.3 总体状态怎样得到

- 一组比较任一硬门槛或适用收敛指标失败，该比较为 `FAIL`；
- 一个工况任一时间步比较失败，该工况为 `FAIL`；
- 任一工况失败，总体为 `FAIL`；
- 只有全部工况比较通过，总体才为 `PASS`。

这里的 `PASS` 只表示冻结的数值有限性、方向、终止一致性和时间步收敛门槛通过，**不表示所有偏差工况都成功插到底**，也不表示实物装配成功。应同时查看每个工况的 `reference_termination`；例如一致地以 `EXCESS_PENETRATION` 结束可以通过“终止一致性”检查，但仍代表该偏差工况触发了数值穿透终止规则。

`failed_checks` 保存机器字段名。技术报告会把失败项转换成可读的工况、时间步、实测值和门槛。不得为了得到 `PASS` 修改阈值、接触参数或删除工况。

## 13. 为什么固定深度网格能隔离时间步影响

旧扫描按“默认速度 × 时间步”决定空间步长。时间步减半时，空间采样也会加密；此时结果变化同时包含两件事：求解器时间步改变，以及取样姿态变多。两者混在一起，不能明确判断差异来自哪里。

V1 三组都使用 10 微米深度增量：

```text
深度点 = 0、10、20、30、... 微米
```

因此同一工况的公共点具有相同 X/Y 偏移、滚转、俯仰和 Z 深度，主要剩下求解器时间步配置的影响。

仍需注意：本程序逐点规定姿态并调用 `mj_forward`，没有用 `mj_step` 积分真实运动。固定网格提供的是**准静态求解器敏感性/收敛证据**，不是机器人速度变化下的动态轨迹收敛。`speed_m_s` 是空间步长除以时间步的派生字段，也不能解释成真实执行速度。

## 15. 常见故障排查

### 15.1 找不到 `D:\KEYANRUJIAN\python.exe`

先在 PowerShell 执行：

```powershell
Get-Command python
```

如果显示另一个 Python 路径，可把本说明命令中的 `D:\KEYANRUJIAN\python.exe` 替换为实际绝对路径。替换前应确认该 Python 能导入 MuJoCo、NumPy、Matplotlib 和 Pillow。

### 15.2 找不到或无法加载 SDF DLL

确认文件存在：

```powershell
Test-Path 'build\dsub9_hole_sdf\Release\dsub9_hole_sdf.dll'
```

新电脑从 GitHub 克隆后通常没有 `build` 目录，需要用本项目 CMake/MSVC 环境重新编译插件。Windows 下保持“项目根目录 + ASCII 相对 DLL 路径”的加载方式，不要改成包含中文的绝对 DLL 路径。

### 15.3 提示缺少 Python 包

```powershell
& 'D:\KEYANRUJIAN\python.exe' -c "import mujoco, numpy, matplotlib, PIL"
```

哪个名字报错，就说明当前 Python 环境缺少对应依赖。不要盲目在多个 Python 中重复安装；先确认正在使用的解释器路径。

### 15.4 中文字体变成方框

程序依次查找 Noto Sans SC、微软雅黑、黑体和宋体。至少安装一种后重新生成五张图。不要交付带方框或缺字的 PNG。

### 15.5 提示 schema 不兼容

本工具只读取 trace schema-1、convergence schema-1 和既有 contact results schema-3。不要手工把版本号改回 1 或 3；应切换到与文件匹配的代码提交，或由维护者编写正式迁移程序。

### 15.6 提示源 SHA-256 不匹配

这表示当前 `reports/contact_validation_results.json` 与生成 trace 时的源文件不同。先执行：

```powershell
git status --short
Get-FileHash -Algorithm SHA256 'reports\contact_validation_results.json'
```

不要直接修改 trace JSON 中的哈希。应恢复正确的 schema-3 基线或在明确审查后重新生成整套 V1 交付。

### 15.7 生成过程中断

JSON 和 CSV 使用临时文件完成后再原子替换，因此中断不应留下半个正式文件。重新运行一条命令即可。若旧结果仍在，可先用 `--check-only` 确认它是否完整。

### 15.8 总体验收为 `FAIL`

先打开 `reports/v1_contact_validation_report.md` 的“总体验收”章节，再在 convergence JSON 中查看 `failed_checks`。`FAIL` 是科学结果，不是要通过调参数隐藏的程序错误。只有出现文件缺失、非有限数、插件加载错误或异常堆栈时，才进入软件排错。

### 15.9 CSV 在 Excel 中乱码或全在一列

文件是 UTF-8 with BOM 和逗号分隔。使用 Excel“数据 → 自文本/CSV”，编码选择 UTF-8，分隔符选择逗号。不要把扩展名手工改成 `.xlsx`。

### 15.10 `--check-only` 提示 CSV 行数不一致

说明 JSON 和 CSV 不是同一次完整生成的配套文件，或其中一个被手工编辑。不要单独修正行数；重新运行完整生成命令，使 JSON、CSV、图表和报告来自同一批数据。

## 16. V1、V2、Failure Boundary 和 RL 的科学边界

| 层级 | 本次是否完成 | 正确含义 |
|---|:---:|---|
| Model V1 | 是 | 刚性几何、正式 SDF、规定姿态准静态接触轨迹和时间步敏感性。 |
| Model V2 | 否 | pin/socket、壳体、夹具等效柔顺以及实物参数辨识。 |
| Controller | 否 | Fixed、Search、Adaptive Admittance 等闭环控制。 |
| Failure Boundary | 否 | 在随机误差、公差和噪声下统计成功/失败概率边界。 |
| Robot/F/T | 否 | 机器人运动学动力学、传感器坐标、采样、噪声和标定。 |
| RL episode | 否 | 按时间演化的观测、动作、奖励、终止和安全约束序列。 |

V1 trace 虽然有按深度排列的样本，但它不是按控制时间推进的 episode。不能直接拿来宣称控制器有效，也不能直接当作 Residual SAC 训练环境。
