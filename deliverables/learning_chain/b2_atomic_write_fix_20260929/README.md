## 已证实与未证实

旧轮在144批SAC更新完成后的账本写入中，`os.replace(update_budget.json.tmp, update_budget.json)`返回WinError 5。异常处理随后保存了相互一致的144批计数与历史，四个预热回合已有效停稳。

同一工作区、同一Windows环境的隔离文件复现：普通只读句柄保持打开时，旧写入函数出现同样的WinError 5，关闭句柄后即成功。原文件当前不是只读，ACL含修改权限；这些事后检查不能证明故障时的全部状态。生产运行没有记录占用句柄或当时的权限变化，无法确认具体进程，也不能归罪于监控、编辑器或杀毒软件。

确定的代码脆弱点是：对可短暂发生的Windows替换拒绝只尝试一次，直接令整个训练周期失败。修复针对这项已真实复现的机制，不声称已还原生产故障的具体占用者。

## 修改与边界

`tools/learning/admitted_collection.py`仅在JSON临时文件完成序列化、flush及fsync之后，对文件替换增加有限重试。只处理Windows的PermissionError 5/32/33；最多9次尝试、累计计划等待1.06秒。每次使用同一个已写好的临时文件，目标始终通过原子替换更新。

没有重新执行SAC更新、经验发布、物理回合或整个函数事务；原始内容不直接覆盖。重试恢复会写明确的`atomic_json_replace_recovered`日志，这种恢复告警本身不表示进程失败，后续跟踪须结合退出码和失败账本判断。

超过上限仍拒绝时保留旧目标及待写临时文件，在原异常中添加重试次数、等待量及文件路径后抛出。其他错误（磁盘满、普通权限错误、目录不存在、fsync失败等）不因本补丁被吞没。每个路径仍遵循原有单写者约定，不支持多个写者同时写同名临时文件。
