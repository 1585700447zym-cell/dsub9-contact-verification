# 实施与验证范围

新 `atomic_repaired_cycle` 将本轮预算限定为 44+32=76，新入口仅绑定目录、资格、台账与累计计数；沿用原有限流程及停止、恢复、独立评价规则。历史文件与旧候选不改写；有变动的 admitted_collection.py 按修复包中的旧字节快照校验旧资格。

新增 10 项入口检查先因缺失新模块全部失败，实现后通过。连同 5 项只读进度页、12 项原子写入、监督器与 Windows 父链校验，首轮 68 项协议检查通过。真实 Windows 子进程仅执行身份/独占声明检查，全部物理、优化与策略推理入口受拦截计数约束，实际计数为 0。

进度页对等待状态不伪造 0 批或成功率，优先读耐久化更新计数，JSON 暂不可读显示缺失提示，有恢复警告的 fault.log 不直接标为失败。Windows 共享句柄测试发现仅设置 FILE_SHARE_DELETE 仍可能阻止替换，因此立即读入内存并关闭句柄后再解析。UI 已在本机浏览器实际检查；不是训练物理可视化，不额外加载仿真或渲染器。

继承的三批合成更新与静态诊断均不重做。正式启动由新候选及本轮授权双摘要锁定，仍有独占启动/工作进程声明。旧 144 批未冒充为可恢复学习状态。

独立审查发现进程探针未纳入测试前后摘要，已将本包五项辅助输入纳入源码闭包；基线复用改为显式读取本包复核凭据。补充一个绑定与凭据来源检查后，最终 69 项全通过，929 项输入绑定，禁止调用计数仍为 0。中间一次新增测试因夹具使用空摘要表被守卫正确拒绝（68 通过、1 失败），修正夹具后通过；旧测试记录保留。
