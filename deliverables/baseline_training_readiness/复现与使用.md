# 本能力的复现与使用

工作目录：`D:\dsub9项目计划\first_stage_sim\.worktrees\dsub9-v1-contact-validation`。先打开根目录的 `D-sub9可视化仿真.code-workspace`。当前训练准入阻塞；下面可以检查或复现证据，不会启动 SAC。

## 文件如何串联

| 层次 | 文件 | 作用 |
|---|---|---|
| 比较入口 | `tools/validation/run_readiness_candidate.py` | 固定候选、校验数值门槛与旧记录、选择初始工况、保存新回合 |
| 候选控制器 | `tools/control/search_probe.py` | 在原 V2 上暂停额外 XY 搜索；本轮入口固定 2.0/0.1 s |
| V2/传统 B2 | `tools/control/search_exit_v2.py`、`search_recovery.py` | 搜索、减载、条件恢复和退出规则；旧实现均未改 |
| 通用回合执行 | `tools/validation/run_b2_search.py` | 每周期读反馈、调用控制器、检查完成/终止、保存过程 |
| 物理环境 | `tools/dynamics/cartesian.py` | 接收速度命令，受限 PD 驱动，MuJoCo 积分，读力和运动状态 |
| 模型生成 | `tools/model/contact_development.py` | 从原模型数据生成当前 256 段碰撞表示，CAD 视觉资产继续复用 |
| 原始结果 | `candidate_pause2_01`～`07` 下 `runs/*.json.gz` | 完整 2 ms 日志、物理步峰值、事件、实际环境和控制配置 |
| 统一评价 | `tools/reporting/report_training_readiness.py` | 读记录并复核完整成功、预算、载荷、终点等，不运行物理积分 |
| 停止诊断 | `tools/validation/measure_readiness_stop.py` / `tools/reporting/report_readiness_stop.py` | 前者运行原 B2 Y 并延续保持；后者只读绘图和重新核验 |
| 训练合同 | `训练合同_v1.md`、`数据划分_v1.json` | 下一能力的实现依据，目前不是可直接运行的 SAC 配置入口 |

原 B2 是本轮保留的传统对照；`candidate_pause2_*` 是未采用的候选，不要因其目录更新就将它当成新的正式基线。

点击 MuJoCo 窗口，P 开始/暂停，N 单步，Q 退出。这里是保存的实际轨迹回放；不能通过回放窗口改变已经发生的控制结果。菜单 01～06 在“运行和调试”的下拉框里，不是文件列表里的文件名。

七项编号依次为：01 同轴、02 X +100 μm、03 Y −100 μm、04 Roll +1.5°、05 联合 A ×0.75、06 联合 B ×0.75、07 联合 A 全幅。每个目录的 results_index.json 记录文件名、参数和 SHA256。

## 重新运行候选

先在 VS Code 打开终端并进入上述工作目录。单回合示例：

```powershell
& 'D:\KEYANRUJIAN\python.exe' -X utf8 -B -m tools.validation.run_readiness_candidate --case y_offset_neg_100um --tag my_y_reproduction
```

该入口验证短回合数值证据、历史指纹和公平字段，用固定参数运行；它是传统候选复现，不代表训练准入通过。输出目录已存在就拒绝覆盖，下一次必须更换 tag。

完整七工况复现：

```powershell
$caseNames = @('aligned','x_offset_pos_100um','y_offset_neg_100um','roll_pos_1.5deg','combined_a_scale_0.75','combined_b_scale_0.75','combined_a')
for ($i=0; $i -lt $caseNames.Count; $i++) {
    $trialTag = 'my_pause2_{0:D2}' -f ($i+1)
    & 'D:\KEYANRUJIAN\python.exe' -X utf8 -B -m tools.validation.run_readiness_candidate --case $caseNames[$i] --tag $trialTag
    if ($LASTEXITCODE -ne 0) { break }
}
& 'D:\KEYANRUJIAN\python.exe' -X utf8 -B -m tools.reporting.report_training_readiness --candidate-prefix my_pause2 --output-tag my_summary
```

只有七回合完整且一致才汇总。新复现必须指定未使用的汇总 output-tag，避免覆盖本次交付。只重绘本轮原图可用 `--candidate-prefix candidate_pause2`；它不重跑动力学。

数值复验另用 `python -m tools.validation.validate_training_readiness --tag my_numeric`；停止延续另用 `python -m tools.validation.measure_readiness_stop --tag my_stop`，其中 python 应使用上面的完整解释器路径。无需为了查看报告重新运行这些耗时实验。

## 源码与机器差异

每次实验的 source_snapshot 保留运行时源码。停止复验完成后，审查修复了验收脚本的最后一步错误识别；旧运行快照及失败记录保留，修复后的只读重判仍失败。物理环境和控制器没有因此修改。

迁移机器时需要完整项目和历史依赖用于指纹核验，不能只复制单个 XML 或脚本。当前物理计算不调用原 SDF 插件，但历史溯源清单包含原资产和 DLL；缺失时应恢复归档或建立新的可追溯复验版本，不能直接删除哈希检查。

本轮相关测试记录在 verification_tests.log 与最终核查文件；原 SDF 插件重新编译存在既知 SDK 权限限制，不属于本轮修复，也不能据此声称全仓库测试全部通过。
