# D-sub9 中文可视化交付包设计说明

## 1. 目标与边界

本任务在已验收提交 `ea00720f64a088ea86008fc03b8fdc218d214421` 的基础上，新增一套面向非软件专业研究生的中文可视化交付包。交付包帮助用户打开正式 SDF 场景和 polygon32 回退场景，理解 9 针—9 孔几何关系，查看既有接触结果图表，并观看明确标注为准静态规定姿态扫描的短动画。

本任务不修改核心碰撞几何、解析 SDF 公式、基线接触参数或已有 schema-3 接触结果，不增加机器人、控制器、强化学习环境、复杂 GUI 或实时参数编辑功能。

## 2. 版本与发布结构

- `main` 在 GitHub 上保存已验收基线提交，作为用户容易找到的稳定版本。
- `feature/dsub9-collision-model` 原样保存既有碰撞模型分支。
- `feature/dsub9-chinese-visual-package` 保存本任务的交接文档、实现、测试和最终产物。
- 不改写既有提交，不把交付分支自动合并到 `main`。
- 完成全部验证后推送交付分支；是否合并由用户决定。
- 推送前检查敏感信息、文件大小、工作区状态和提交范围。

## 3. 总体方案

采用“统一 Python 核心 + 薄启动脚本 + 静态交付产物”的结构。共享模块统一处理项目根目录定位、正式插件注册、模型加载、案例位姿、中文字体和免责声明，避免四个脚本各自复制易漂移的逻辑。

交付包位于 `deliverables/chinese_visual_package/`，实现位于 `tools/visualization/`，自动测试集中位于 `tests/visualization/`。用户双击两个中文 `.cmd` 启动器即可打开场景，也可按说明书中的命令重新生成截图、图表和动画。

## 4. 组件设计

### 4.1 共享基础模块

共享模块负责：

- 从任意当前目录可靠定位项目根目录；
- 检查指定 Python、MuJoCo、XML、DLL 和模型资产；
- 在项目根目录下用 ASCII 相对路径注册正式 SDF 插件；
- 加载正式 SDF 或免插件 polygon32 模型；
- 为对齐、正 X 偏移 100 微米、组合偏差等案例设置规定姿态；
- 提供统一中文工况名称、模型名称和免责声明；
- 探测并选择可显示中文的字体。

共享加载逻辑只改变运行时显示选项和规定姿态，不写回基线 XML，也不修改模型的物理接触参数。

### 4.2 一键启动器

两个 `.cmd` 文件从自身位置反向定位项目根目录，并固定调用 `D:\KEYANRUJIAN\python.exe`。正式启动器检查和注册 SDF DLL 后加载 `models/dsub9_pair.xml`；回退启动器不注册 DLL，缺少回退 XML 时才调用既有生成器安全重建。

Python 入口执行完整前置检查并打开 `mujoco.viewer`。错误信息使用中文，说明缺失项和可执行的修复步骤；由 `.cmd` 在失败时保留窗口，防止报错瞬间消失。

### 4.3 静态截图

渲染程序复用同一套模型与位姿逻辑，生成六张至少 1600×900 的 PNG：对齐总览、碰撞几何叠加、九针九孔局部放大、正 X 偏移 100 微米、组合偏差工况 A，以及正式 SDF 与 polygon32 同相机对照。

优先使用 MuJoCo 离屏渲染。若环境失败，只进行一轮有证据的系统化诊断；仍无法工作则改用允许的可见 viewer 截图路径并记录生成方式。标题和图注由图像合成层添加，不修改模型文件。

### 4.4 图表与摘要 CSV

图表程序只读 `reports/contact_validation_results.json`，校验 schema 版本和必要字段后生成峰值合力、峰值合力矩、最大穿透量三张中文图表及 UTF-8 BOM 中文摘要 CSV。

每条结果通过“工况 + 模型类型 + 接触配置 + 必要时的时间步或敏感性标签”唯一标识。主配置、low-response 和 high-response 分组展示，不把两条替代配置描述成覆盖全部工况，也不构造数据中不存在的连续曲线。图表固定显示“未经过实物标定，仅用于数值敏感性分析”。

### 4.5 准静态动画

动画使用规定的一系列位姿调用 `mj_forward` 渲染，不运行自由动力学。内容依次展示分离、接近、对齐、正 X 偏移和组合偏差姿态，并在每帧固定显示：

> 准静态规定姿态扫描演示；不是自由动力学插入，不包含机器人或力控制器。

当前环境无可用 FFmpeg，已有 Pillow，因此默认生成 10–20 秒 GIF，不安装大型编码器。

### 4.6 中文使用说明

`中文使用说明.md` 面向第一次使用 MuJoCo 的研究生，覆盖交接文档要求的 20 个主题，并提供三分钟快速开始、逐图说明、图表解读、常见故障排查、重新生成命令、不可随意修改的核心文件，以及下一阶段机器人与柔顺控制研究的接入边界。

## 5. 数据流与不可变性

模型加载链路为“项目定位 → 依赖与资产检查 → 可选插件注册 → XML 编译 → 运行时位姿/显示设置 → viewer 或渲染器”。结果生成链路为“只读 schema-3 JSON → 严格字段校验 → 中文标签映射 → PNG/CSV”。

实现和测试保存基线 XML、JSON 与碰撞资产的哈希或内容快照，验证生成过程没有写入这些文件。`reports/contact_validation_results.json` 的 SHA-256 必须保持为 `ac767ea63a7e8a6866a974728a1256e688832003076170e270cd181e5c9d65ff`。

## 6. 错误处理

- 缺少指定 Python：启动器显示预期路径和换电脑后的修改位置。
- 无法导入 MuJoCo：显示当前解释器及安装建议，不自动安装软件。
- DLL 缺失或未注册：区分“文件不存在”“路径不正确”“插件未注册”，并提示使用项目根目录和相对路径。
- XML 或资产缺失：显示准确相对路径；正式模型不自动重建核心资产。
- 回退 XML 缺失：调用既有确定性生成器；生成失败时保留原始错误上下文。
- 中文字体不可用：报告探测结果并停止生成中文图片，避免交付乱码。
- JSON schema 或字段不符：拒绝生成误导性图表，不猜测数据含义。
- 渲染失败：仅允许一轮环境修复，然后采用交接文档允许的回退或明确报告阻塞。

## 7. 测试与验证

实现采用测试先行：先写失败的可视化相关测试，再完成最小实现。测试覆盖项目定位、正式/回退加载行为、启动器错误提示、JSON 分组和标签、CSV 数值一致性、图片分辨率与中文字体、动画可读性和免责声明，以及基线文件不变性。

开发期间只运行 `tests/visualization/` 和受影响的小范围既有测试。所有最终产物完成并人工查看后，运行一次完整测试；记录通过数、跳过数和用时。随后扩展并刷新 reproducibility manifest，使 `deliverables/`、新增工具、测试和设计文档均进入清单，再验证清单一致性。

## 8. 人工检查与完成条件

逐张查看六张截图和三张图表，抽查动画首、中、末帧，确认相机、构图、中文、单位、免责声明和 SDF/polygon32 区分无误。完成一次集中代码与交付审查，修复所有关键问题，确认工作区干净后提交。

只有实际验证通过才能声明完成。最后将稳定基线分支和交付分支推送到用户指定的 GitHub 仓库；若网络或认证阻塞，保留本地已验证提交并给出最短登录或重试步骤。
