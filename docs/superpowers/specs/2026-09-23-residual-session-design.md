# 阶段 B 共用回合管理与残差接口设计

2026-09-23。根据用户同意的综合审查建议形成书面设计。本次交付是文档，尚未实现下列模块。当前执行规范为[训练合同v3](../../stage_b/训练合同_v3.md)。

## 目标与边界

将现有一次运行完整回合的B2编排提炼为可逐周期推进的共用会话。基线回放、残差训练、策略评价读取同一会话逻辑；物理积分、基线控制器和历史归档优先复用。保留现有工作树与未提交资产，不创建从主分支开始的替代工程。

本次设计不引入新机器人、学习导纳、风险网络或新碰撞模型。现有`tools/validation/run_b2_search.py`、冻结控制器和历史文件继续作为比较参照，不就地重写其已验收行为。

## 核心接口

`EpisodeSession.reset(case, seed) -> CycleSnapshot`：重置物理、重建或重置基线、所有历史/计时/恢复/奖励和暂存区，准备首周期。

`EpisodeSession.prepare_cycle() -> CycleSnapshot`：幂等；同一物理时间重复调用返回同一缓存。按原时序处理回合前置事件，只在基线本应更新时调用一次command。周期编号和物理时间作为重复更新断言。

`EpisodeSession.advance_cycle(action4) -> CycleResult`：仅在尚未最终完成时接受四维有限动作，消费本周期缓存，按2ms步进并裁决。动作屏蔽不代替输入有效性检查。结果含下一周期可用状态、实际Δt、周期峰值、分项奖励、事件和待结束/最终审核状态。

`EpisodeSession.observe() -> CycleSnapshot`：只读缓存，不调用command，不推进积分或成功保持计时。向调用方返回不可变对象或独立副本。

`ResidualEnv.reset(*, seed=None, options=None)`及`step(action4)`返回标准观测/奖励/terminated/truncated/info；只能委托会话推进。案例只能由明确配置/种子生成，不能在初始化失败后悄悄重采样。

每个CycleSnapshot必须携带时间、周期号、合法策略观测、未归一化可测量日志、基线命令及其阶段、残差权限和独立privileged_evaluation。CycleResult必须另含实际执行命令、实际Δt、周期统计、事件列表、奖励分项和结果审核状态。

## 共用状态与停止计时

会话拥有原run_search_episode中的reason、stop_time、hold_start、recovery_state、wait_start、guard_latched及其转移。controller内部历史、相位和导纳状态由基线对象拥有，会话在reset时确保完全隔离。

区分基线阶段、物理阶段、任务待定结果、最终审核结果四种状态；“任务已决定失败”和“物理已停稳”不能合并。最终STOPPING计时沿用已验证的actual_stop_start语义，同一停止段附加保护事件不重启时钟；真正回撤后再停止才建立新停止段。

任务窗口结束即锁定成功机会；安全尾段只补齐安全/有效性证据和时间成本。有限未停稳单列，整回合不学习。正常回撤按原条件仅一次，实际回撤不足不得恢复；不会因最终审核失败再次回撤。

## 采样和事件边界

按每次积分后原采样时机统计物理子步，观测周期内峰值；周期统计在advance_cycle开始时清零，累计峰值维持回合锁存。不得全局替换mujoco.mj_step作为常驻训练方案，以免并行环境串扰。

新增环境适配优先使用独立子类/实例回调复用原数值推进。不为方便记录改变求解器、步长、mj_forward顺序或驱动公式。若确需改共同物理主循环，先建立版本、差异测试和必要重评；不直接刷新旧哈希。

有效性与守卫先形成事实集合，再按v3顺序确定原因。STOPPING仍持续记录超限事件，但不重新给动作权限或延长停稳预算。实际姿态限值必须有参数冻结依据，尚未确定可用数值时初始化训练入口失败，而不是给无限默认值。

## 学习数据和动作语义

使用四维归一化请求动作作为critic的动作；共同映射和守卫是环境的一部分，六维执行命令另存。无权限状态的规范动作是零，保留有效标志；actor/温度仅用有权限样本，critic目标的熵项按下一状态权限处理。

整回合缓存保存有限、可序列化转移。收到最终审核后提交或隔离，不能先让学习库消费再删除。异常保存使用明确nonfinite标记，不能以零替代异常。

正常rollout批次结束仅分批，不结束任务。真正外部截断捕获当时下一状态并保留bootstrap语义，独立停止审核不覆盖该状态。无效回合全部排除，但全部尝试保留在评价记录中。

## 零残差与共同版本

先在不改变原保护行为的兼容配置下，逐周期比较历史七个B2开发工况的命令、物理状态、阶段、事件和终止，建立纯封装无行为改变的证据。数值容差预先声明，禁止按失败结果放宽；同运行环境优先要求原始数值一致。

新增共同姿态/事件规则独立版本化；零残差随后必须等同于该版本的B2。若新规则实际改变旧轨迹，承认共同环境版本改变并重评受影响对照，不能同时声称与旧B2完全一致。
