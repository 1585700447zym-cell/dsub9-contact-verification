## 1 项目目标和当前判断

研究简化D-sub9多针插接中的残差强化学习：传统导纳、搜孔和恢复控制器B2提供基本命令，SAC学习受限修正，研究阶段或进展相关权限是否优于合理的固定边界。

用户优先目标是完成有真实证据、比较公平、逻辑闭环的小论文，普通期刊或四区、会议均可。允许合理调整场景、几何和方法，但各基线必须共享新条件并重新评价，不能削弱基线、改写历史结果或把任务变容易当算法贡献。

当前学习和评价链路能够运行，位置范围短训、保存/加载和冻结评价里程碑已完成；完整B.2、C与论文优势尚未验收。开发点有学习收益，四个首次位置没有显示稳定优势。不要沿“全部SAC训练都失败”或“没有运行故障就证明方法有效”的前提推导。

## 3 当前场景与控制接口

| 项目 | 当前实际设置 |
|---|---|
| 场景 | 固定母头、带9根刚性针的公头、简化笛卡尔动态执行器；无完整机械臂/夹爪 |
| 接触模型 | MuJoCo native接触、256段凸分块孔碰撞表示；不能把早期SDF插件当当前训练后端 |
| 几何 | 主孔直径1.20mm，针直径1.00mm；以冻结运行包model.xml为准 |
| 初始误差 | 开发点为对中、X±150μm、Y±150μm；四首次位置径向约127～139μm |
| 初始姿态 | 本轮roll/pitch/yaw均0；没有位置—姿态联合初始扰动。接触后产生倾斜不等于做过联合误差实验 |
| 反馈 | 仿真计算六维接触力/力矩及位姿/速度；无独立实体传感器噪声、偏置或延迟模型 |
| 策略观测 | 137维：旧120维加17个驱动/控制器状态；已有部分冗余核对，没有137维必要性的消融证明 |
| 学习动作 | 4维归一化速度残差，映射为`[Δvx, Δvy, 0, Δωx, Δωy, 0]` |
| 当前最大尺度 | XY各50μm/s；绕X/Y各0.5mrad/s；Z由基线与回合管理负责，未开放独立yaw学习修正 |
| 时间尺度 | 控制周期2ms，物理子步0.2ms，正常每周期10子步；折扣按`exp(-dt/10s)` |
| 共同保护 | 力25mN、力矩0.5mNm、穿透30μm等；详见冻结configuration.json，不自行放宽 |

起点`start_origin_z_m=-0.004`，`target_depth_m=0.004`表示从起点推进4mm，目标公头原点Z约0；不要误读为目标世界Z=+4mm。

功能成功要求当前深度、九针分层几何适配、载荷、速度和停稳等条件。80μm/0.5°是另列的附加精度，不等同于功能成功。50μm/s动作尺度、80μm精度、120μm搜索参考半径和200μm实际搜索位移保护是不同量。

关键名称：B1是固定导纳基线，B2是带搜孔/卸载/恢复的基线；B.1/B.2是项目阶段。F50在INSERT/SEARCH允许固定尺度残差；S50只在SEARCH允许。零残差执行B2；F0/S0是随机初始化、0更新的网络，动作并非全零。

## 5 是否使用了标准 SB3 SAC

当前导入`stable_baselines3.sac.policies.SACPolicy`，复用其actor、双critic、目标网络和动作分布；PyTorch负责求导与优化器。经验池、训练调度、目标计算、actor/温度更新与软更新由项目组织，并未直接使用完整`stable_baselines3.SAC(...).learn(...)`流程。

另有非活动状态的actor/温度屏蔽、物理时间折扣、critic边界重采样、部分精确终末尾段目标替换。不能把当前实现称为未经修改的标准SB3 SAC。标准SB3残差基线仍未完成；不是完全从零写网络，也不是成熟库自动包办整个训练链。

经验必须经过完整回合审核；有效停稳的普通失败与无效仿真分开。确定性评价不进入训练经验池。当前完整恢复针对已审核回合边界，不能承诺任意物理子步断点续跑。

## 7 排错时必须区分的事情

- 请求残差、受限总命令、驱动参考和实际运动分开。`effective_command_delta`仅为同一历史状态下与零替代动作的命令差，不能当残差造成的真实位移。
- 旧`clipped`口径是请求与即时零替代差不等；历史命令包含持续残差，因此高占比不证明动作未执行。PC-08另统计了总目标与最终驱动命令是否不等，且此目标已过阶段上限。
- 三份档案各275个禁用残差的回撤周期，共825个预测/实际命令差，来自环境接管Z向回撤；保留记录，不能直接归为SAC命令错误。
- 程序报错、无效仿真、未停稳、合格任务失败、合格保护失败与无性能收益分别解释。SB3训练器不能自动修复错误的环境/状态机。
- 历史120维训练的critic危险边界约+9.364、精确轨迹尾段约−8.359，失败样本已使用；不能误说“漏用了失败样本”，也不能称新评价已统一解决该历史高估。
- 已有复杂度审查指出复制代码和多层封装，见[审查报告](../deliverables/project_audit/complexity_20261006/客观审查与修复优先级.md)。不要先扩维、增学习层或复制一套v5来处理控制故障。
