# 新电脑安装、仿真及F4000续训

适用分支：`snapshot/five-axis-sac-20261102`。本次补充迁移包约 **86.3 MiB**，直接存放在该分支的 `migration/`，下载分支ZIP会一并下载。无需再下载12GB旧完整备份。

## 一、先准备电脑

- Windows x64，Python **3.13 x64**；原电脑使用3.13.5。这里的MuJoCo二进制是Windows/Python 3.13专用，不能直接用于Linux、macOS或其他Python次版本。
- 联网安装通用Python依赖。当前为CPU训练配置，不要求CUDA或独立显卡。CPU性能会影响耗时，跨电脑不保证逐位一致的数值轨迹。
- 磁盘建议预留数GB：压缩包约86.3 MiB，解包资料约数百MiB，Python依赖还要占空间。仅CPU PyTorch当前安装约498 MiB；这不是完整离线环境包。
- 若系统提示VCRUNTIME140/MSVCP140缺失，安装微软官方x64 Visual C++运行库。无需为了当前原生凸分块模型编译旧SDF插件。

Git下载：

```powershell
git clone --branch snapshot/five-axis-sac-20261102 --single-branch https://github.com/1585700447zym-cell/dsub9-contact-verification.git
cd dsub9-contact-verification
```

也可在GitHub切到上述分支，选择Code → Download ZIP，完整解压后进入项目根目录。不要只下载单个脚本。支持项目路径含中文和空格。

## 二、安装和恢复（不会启动训练）

在项目根目录打开PowerShell：

```powershell
powershell -ExecutionPolicy Bypass -File tools\migration\install_windows.ps1
```

若电脑没有`py`启动器，可指定Python 3.13的完整路径：

```powershell
powershell -ExecutionPolicy Bypass -File tools\migration\install_windows.ps1 -Python "C:\Python313\python.exe"
```

脚本只做以下操作：在本项目创建`.venv`、按`requirements-migration-20261102.txt`安装通用依赖、核对三个包的SHA256并解包到`.migration`、生成本机路径记录、恢复检查完整F4000状态，以及导入MuJoCo/编译模型XML。**不调用环境reset/forward/step，不做策略前向，不更新参数，不自动启动任何批次。**

依赖已经安装时可加`-SkipInstall`。检查失败时先保留输出，不要运行后面的仿真/训练命令。

手工恢复、检查的等价入口：

```powershell
.\.venv\Scripts\python.exe -B -m tools.migration.package
.\.venv\Scripts\python.exe -B tools\migration\run_f4000.py --check --compile-model
```

正常检查应显示各类更新计数4000、回放162274条、策略摘要`570a2eee...59cfe`、MuJoCo3.13.0，以及本次reset/物理步/推理/更新均0。

移动整个项目目录后，再执行恢复命令即可重建本机路径。已有恢复文件必须仍与原摘要一致；已改动的文件不会被静默覆盖。旧绝对路径只保存在原始来源记录内，不用于本机定位。

## 三、这次恢复了什么条件

完整F4000来自2026-10-29：网络、目标网络、温度、优化器、回放、随机数状态和训练历史均从原`state.pt`恢复。文件原字节不改写。

为保持这些状态的语义，迁移入口明确使用包内一份冻结训练引擎：**原1nm成功几何容差、2ms动作采样、30s时限、G1五维尺度、N2、400μm半径及原奖励/保护**。它继承原已通过的配置/来源/资格证明，未来每个新回合仍必须通过停稳、动作来源、参考限制和数据审核，才能入池及更新。没有声称新电脑已重新完成物理资格试验。

根目录当前源码仍保留后来改过的**10nm判据**及**50ms探索诊断**，本次没有回滚它们。它们与旧F4000回放属于不同执行条件。以后要在新条件下训练，应另外登记配置及旧回放使用方案；这里不静默混用，也不把纳米口径修订算作训练收益。

## 四、以后需要运行仿真时

以下命令仅供以后明确决定运行时使用；本次交付没有执行`--run`。

先登记一个零更新仿真：

```powershell
.\.venv\Scripts\python.exe -B tools\migration\run_f4000.py --prepare --purpose simulation --episodes 1 --updates-per-episode 0 --output experiments\f4000_simulation_01
```

该命令只写登记，不重置环境、不做策略前向或物理推进。确认登记后，显式启动：

```powershell
.\.venv\Scripts\python.exe -B tools\migration\run_f4000.py --run --output experiments\f4000_simulation_01
```

这会实际运行原条件下的F4000确定性仿真并保存轨迹/审核，**不入池、不更新权重**。默认第一个工况为X/Y各+0.30mm、roll−1°、pitch+1°、yaw+1°；多个回合按原四个开发工况循环，不代表最终测试。

## 五、以后需要从F4000续训时

例如，登记4个回合、每回合500次更新：

```powershell
.\.venv\Scripts\python.exe -B tools\migration\run_f4000.py --prepare --purpose continuation --episodes 4 --updates-per-episode 500 --output experiments\f4000_continuation_01
```

这时仍未开始训练。确认新批次配置后，显式执行：

```powershell
.\.venv\Scripts\python.exe -B tools\migration\run_f4000.py --run --output experiments\f4000_continuation_01
```

只有第二条命令才启动。入口最多允许8个回合、每回合最多500次更新；从4000次状态接续，例子完成后总更新应为6000。每回合完整收集并审核通过后才入池/更新，再保存含回放和优化器的新完整检查点。所有输出均写到指定新目录；旧目录已有批次时拒绝覆盖，不自动重试或接着半个失败回合跑。

本入口针对**从发布的F4000开始一个新批次**；不自动恢复中断中的物理回合，也不擅自把其他批次结果当成来源。新保存文件保留，后续若要从它继续，应再明确来源与计划。

运行期间可查看`summary.json`、`run/<回合>/progress.json`、`update_progress.json`及日志。未完成/异常退出时，合并已落盘进度并标记计数下界，不能把占位0当作无消耗。正常有效任务/接触保护失败保留；无效、越域、来源/审核/更新/保存失败停批。`STOP`文件用于以后运行时请求在边界停批，实际停止以退出证明为准。
